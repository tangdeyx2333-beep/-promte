### 3. `task.md`：实现任务计划

**核心目标：让 Agent 能够根据计划自主开发，让用户能够追踪任务完成情况。**

根据已确认并通过评审的 Spec，将需求拆分为可执行、可验证的任务。

#### 每个任务必须包含

- 任务编号与名称。
- 目标结果。
- 主要涉及范围。
- 前置依赖。
- 完成检查方式。
- 当前完成状态。

使用以下状态标记：

- `- [ ]` 未完成。
- `- [x]` 已完成。

任务应尽量能够独立验证。

例如，“完成坐标转换并验证缩放和平移结果”比“完成地图功能”更容易检查。

#### 执行要求

- Task 描述实现目标和关键步骤，不要求规定每个方法的具体编写顺序。
- Agent 可以自主决定普通实现细节。
- Agent 可以在不改变需求目标的前提下调整任务内部的执行顺序。
- 任务完成后必须更新状态。
- 不得仅因为代码已经编写，就将任务标记为完成；必须满足对应的完成检查条件。
- 发现计划无法执行时，应分析原因并修订计划。
- 涉及重大方案变化时，必须重新评审；改变已确认需求时，还必须重新提交用户确认。
